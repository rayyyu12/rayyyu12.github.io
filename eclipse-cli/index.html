Eclipse CLI

A terminal trading client for Solana memecoins, with a copy trader that spots a trade from any wallet it's watching and fires its own before the original has confirmed.

C++17 · Solana · Jito · Yellowstone gRPC

C++ client on GitHub

What it does

Eclipse is a menu-driven Solana trading client that lives in the terminal. It shows your holdings with size, average entry and live profit and loss, and it places buys and sells itself, building, signing and sending each swap and routing it to pump.fun's bonding curve or to the Raydium pool the token graduated to.

Its copy trader watches a list of wallets. The moment one of them buys or sells, Eclipse decodes the trade, builds a matching swap and sends it, before the original transaction has even confirmed. Its own settings decide how much to spend (a fixed amount, or the same size as the wallet it's copying, within limits), the slippage, and which venues to follow. At the time, copiers this fast sold for thousands of dollars and almost nothing public explained how they worked. This one was built from scratch.

Against a paid copier

To check the speed, a buy from Eclipse was also copied by a commercial copy trader that sold for thousands of dollars. The numbers below come straight from each tool's own log in these two clips.

One run each, on different trades, so read it as the same league rather than a lab benchmark.

How it works

  • Copying before confirmation. The copier streams the watched wallet's transactions from a dedicated Solana node over Yellowstone gRPC, decodes each swap as it arrives, and rebuilds it from cached pool data, so its own transaction is signed and on the wire within milliseconds.
  • Built from the wire format. The C++ rewrite writes base58, ed25519 signing, program-derived addresses, shortvec prefixes and message compilation by hand in about 600 lines, with no Solana SDK. Nothing can break on a version bump, and nothing sits between the code and the bytes that reach the validator.
  • Tested where mistakes cost money. 43 checks pin the risky parts to known values. Address derivation, for one, is checked against Raydium's published AMM authority, which only comes out right if the hashing, bump search and curve check are all correct.
  • Nothing left stranded. Buys wrap SOL in a throwaway account that is opened and closed inside the same transaction, so a failed swap can't strand wrapped SOL. Keys are encrypted at rest with AES‑256‑GCM.

About the code

The copy trader in these videos is from Eclipse's original TypeScript build, from January 2025, which is private. The repository on GitHub is the later C++17 rewrite of the trading client, which doesn't include the copy trader.
