Tophat

Automation for a daily NQ futures strategy, run across several prop‑firm accounts from the first evaluation to the final payout.

Python · FastAPI · ProjectX API · Monte Carlo

Source on GitHub

What it does

Tophat trades one simple idea many times over. Each morning it watches which way NQ moves between the 8:30am CT open and 8:45am, locks that in as the day's drive, and sends a single bracket order in that direction to every account it manages.

The hard part is everything around the trade. Prop-firm accounts move through a lifecycle of evaluation, funding, payout cycles and retirement, each under a trailing drawdown floor and rules that differ from firm to firm. Tophat tracks where every account sits in that lifecycle and decides what each one should trade today, or whether it should sit out.

Where the edge comes from

Most automated strategies built by retail traders have no real edge, and on its own, this one doesn't either. NQ's intraday moves are close enough to a random walk that the trade by itself isn't profitable long term. The opening-drive signal helps, but only a little.

The edge is in how prop firms work. An evaluation costs around $85, and that fee is the most an account can ever lose. A funded account can pay out up to $2,000 at a time, so a single payout covers more than ten new accounts. Across enough accounts, that lopsided payoff is profitable even if the direction of each trade were a coin flip, and the drive signal is upside on top. Tophat exists to play that game at scale and by the rules.

Working with Claude

I built Tophat with Claude as a working partner, and it wouldn't exist without it. Writing the code was the smaller part. The bigger one was the research: Claude ran the backtests, Monte Carlo simulations and statistical analyses that turned a rough idea into a fine-tuned set of parameters, then helped apply them to the live system. Together we worked out:

  • which prop firms and account types suit the strategy, and whether to take accounts with a daily loss limit
  • which account size returns the most per dollar spent, where a 50K account beat a 150K
  • contract size, and the profit target for each nuke and flip
  • what time to enter, and how to stagger entries so the accounts don't all ride on one trade
  • the expected value of each account, and how often to buy new ones

None of it was guessed. Signals were chosen before testing, checked out of sample and against coin-flip controls, audited before going live, and then compared against real results.

How it works

  • Leaders and mirrors. Topstep accounts are traded directly through the ProjectX API, and their outcomes are determined from balances. Firms with no API are run as mirrors: Tophat models their state by inference, scaling the leader's result and applying each firm's own rules.
  • Rabbit, the bridge. A small service on the Windows box that runs the trade copier. Every night it pulls the desired copier layout from Tophat, closes the copier, backs up and rewrites its database, relaunches it and checks its own work. If anything looks wrong, it rolls back and reports to Discord.
  • Simulation on the live code. Backtests and Monte Carlo runs replay NQ tick data, rolled up into 1‑second bars, through the same lifecycle engine that trades live, so the simulator and the real system cannot drift apart. The same seed always gives the same result.
  • Risk built into the scheduler. Daily caps on high-risk legs per API key, staggered entry times so the fleet never enters at once, a hedge guard that skips any account that isn't flat, and one attempt per account per day.
