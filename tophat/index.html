Tophat

Automation for a daily NQ futures strategy, run across a fleet of prop‑firm accounts from the first evaluation to the final payout.

Python · FastAPI · ProjectX API · Monte Carlo

Source on GitHub

What it does

Tophat trades one simple idea many times over. Each morning it watches which way NQ moves between the 09:30 open and 09:45, locks that in as the day's drive, and sends a single bracket order in that direction to every account it manages.

The hard part is everything around the trade. Prop-firm accounts move through a lifecycle of evaluation, funding, payout cycles and retirement, each under a trailing drawdown floor and rules that differ from firm to firm. Tophat tracks where every account sits in that lifecycle and decides what each one should trade today, or whether it should sit out.

How it works

  • Leaders and mirrors. Topstep accounts are traded directly through the ProjectX API, and their outcomes are reconciled from balances. Firms with no API are run as mirrors: Tophat models their state by inference, scaling the leader's result and applying each firm's own rules.
  • Rabbit, the bridge. A small service on the Windows box that runs the trade copier. Every night it pulls the desired copier layout from Tophat, closes the copier, backs up and rewrites its database in one transaction, relaunches it and checks its own work. If anything looks wrong, it rolls back and reports to Discord.
  • Simulation on the live code. Backtests and Monte Carlo runs replay 1‑second NQ bars through the same lifecycle engine that trades live, so the simulator and the real system cannot drift apart. The same seed always gives the same result.
  • Risk built into the scheduler. Daily caps on high-risk legs per API key, staggered entry times so the fleet never enters at once, a hedge guard that skips any account that isn't flat, and one attempt per account per day.
